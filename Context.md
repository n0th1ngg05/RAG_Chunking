# Project Context — Document Processing and RAG System

## 1. Tech Stack

- **Backend / Core Functionality:** Python
- **Middleware, Request Handler, and Database Queries:** Node.js
- **API Testing:** Postman, targeting the Node.js APIs
- **Database:** PostgreSQL
- **Vector Database:** pgvector (PostgreSQL extension)
- **Authentication:** JWT + RLC (as specified; exact meaning of RLC has not yet been clarified)

## 2. Document Processing Pipeline

1. Accept uploaded documents in restricted formats.
2. Parse the document and extract text.
3. Use OCR, such as SuryaOCR, for images and scanned content where required.
4. Use a VLM for diagrams, images, and visual content requiring interpretation.
5. Chunk the extracted and processed content.
6. Generate embeddings for the chunks.
7. Store chunks and embeddings in PostgreSQL using pgvector.
8. Retrieve relevant chunks through vector similarity search.

## 3. Database Schema

### 3.1 `users`

| Parameter | Data Type | Constraints / Description |
|---|---|---|
| `id` | `BIGINT` | Primary key, auto-generated |
| `name` | `VARCHAR(150)` | NOT NULL |
| `dob` | `DATE` | Date of birth |
| `username` | `VARCHAR(50)` | UNIQUE, NOT NULL |
| `password_hash` | `TEXT` | NOT NULL; securely hashed password |
| `email` | `VARCHAR(254)` | UNIQUE, NOT NULL |
| `contact_no` | `VARCHAR(20)` | Contact number |
| `user_type` | `VARCHAR(30)` | NOT NULL, default `user` |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, default `NOW()` |

### 3.2 `documents`

| Parameter | Data Type | Constraints / Description |
|---|---|---|
| `id` | `BIGINT` | Primary key, auto-generated |
| `document_name` | `VARCHAR(255)` | NOT NULL |
| `uploaded_at` | `TIMESTAMPTZ` | NOT NULL, default `NOW()` |
| `uploaded_by` | `BIGINT` | Foreign key referencing `users.id`, NOT NULL |
| `size_bytes` | `BIGINT` | NOT NULL; must be greater than or equal to zero |
| `file_type` | `VARCHAR(20)` | NOT NULL; accepted formats: JPG, JPEG, PNG, PDF, DOCX, TXT |
| `mime_type` | `VARCHAR(100)` | NOT NULL |
| `status` | `VARCHAR(20)` | Default `pending`; allowed values: `pending`, `processing`, `completed`, `failed` |

### 3.3 `document_chunks`

This table serves as the vector store using pgvector.

| Parameter | Data Type | Constraints / Description |
|---|---|---|
| `id` | `BIGINT` | Primary key, auto-generated |
| `document_id` | `BIGINT` | Foreign key referencing `documents.id`, NOT NULL |
| `chunk_index` | `INTEGER` | NOT NULL; sequential chunk number |
| `content` | `TEXT` | NOT NULL; extracted text chunk |
| `embedding` | `VECTOR(768)` | NOT NULL; embedding generated by the selected embedding model |
| `page_number` | `INTEGER` | Nullable; source page number |
| `metadata` | `JSONB` | Additional chunk metadata; default empty JSON object `{}` |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, default `NOW()` |
| Unique constraint | — | `UNIQUE (document_id, chunk_index)` prevents duplicate chunk indexes within a document |

**Note:** The embedding dimension of 768 is provisional and must match the selected embedding model's output dimension.

## 4. Security Measurements

- Restrict accepted file formats.
- Apply resource restrictions to Python processes.
- Use JWT for access control.
- Track the uploader through the `uploaded_by` field.
- Use PostgreSQL Row-Level Security (RLS) if “RLC” refers to RLS.
- Enforce document ownership during retrieval.

## 5. Python Process Management

- Keep the Python process alive.
- Evaluate processing ETA.
- Decide whether to reuse the existing process or spawn a new process and terminate it after completion.
- The preferred direction discussed was to keep the worker alive rather than spawning and killing a process for every document.
